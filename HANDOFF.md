## 1. Цель проекта

Интерактивный frontend-прототип финансового приложения **Fin Money** (UI-кит и демо для показа инвесторам). Бэкенда нет, все данные моковые.

**Важно:** изначально по `контекст.txt` и мобильному макету это был мобильный интерфейс в рамке телефона. Позже пользователь **явно попросил перейти на веб-версию** по десктопному макету лендинга, а затем сделать в веб-стиле и все экраны. Сейчас проект — адаптивное **веб-приложение**: на десктопе боковое меню, на телефоне нижняя панель, как в мобильном макете. Рамки телефона больше нет.

## 3. Команды

```bash
npm install        # установка зависимостей
npm run dev        # dev-сервер (Vite), по умолчанию http://localhost:5173
npm run build      # продакшн-сборка в dist/ (проверка, что всё компилируется)
npm run preview    # просмотр собранной версии
npm run test:e2e   # сквозные тесты Playwright (e2e/), сами собирают сайт и запускают preview на 4173
```

На этой машине скачанный Playwright Chromium не стартует (ошибка «side-by-side configuration»), поэтому e2e запускаются с установленным Chrome: `$env:PW_CHANNEL='chrome'; npm run test:e2e`, а из песочницы Claude Code — только с отключённой песочницей (иначе `spawn UNKNOWN`). На GitHub Actions работает обычный Chromium.

`.claude/launch.json` содержит две конфигурации превью: `fin-money` (`npm run dev -- --port 5173 --strictPort`) и `fin-money-preview` (собранная версия, `npm run preview -- --port 4173 --strictPort`).

**Публикация:** Netlify, способ «через GitHub» — после `git push` в `main` сайт собирается сам. Настройки сборки и кэширования — в `netlify.toml`. Картинка превью ссылки — `public/og-image.png` (1200×630). Сайт: https://fin-money-app.netlify.app (этот адрес прописан в `og:url`, `og:image` и `canonical` в `index.html`). Репозиторий: https://github.com/Yaroslav0123/fin-money (публичный, коммиты с почтой `…@users.noreply.github.com`).

**Проверка:** `npm run lint`, `npm test` (Vitest: расчёты, контекст, диалог суммы, CSV), `npm run build`, `npm run test:e2e` (лендинг → демо, меню, новая операция и сохранение, тёмная тема, экспорт и импорт CSV, телефон), плюс ручной просмотр в браузере на ширине 1280, 375 и 320 px. То же самое, кроме ручного просмотра, запускает GitHub Actions (`.github/workflows/ci.yml`) на каждый push в `main`.

**Скорость загрузки.** Лендинг не тянет код приложения: экраны и `AppShell` подключаются через `React.lazy` в `App.jsx` и подгружаются заранее в свободное время браузера. Графики (recharts, ~115 КБ gzip) тоже отложены — компоненты импортируются из `components/charts/lazy.jsx`, пока они грузятся, на их месте пустой блок того же размера. Первая загрузка — ~120 КБ JS gzip вместо ~250.

**Метрика и Sentry** (`utils/monitoring.js`) включаются только в продакшн-сборке и только при переменных окружения Netlify `VITE_YM_ID` / `VITE_SENTRY_DSN`. Без них код Sentry даже не попадает в сборку. Экраны приложения отправляются в Метрику как просмотры `/#screen`. Вебвизор выключен. Когда мониторинг включён, в «О проекте → Данные и конфиденциальность» появляется абзац `monitoringParagraph`.

## 4. Архитектура

```
src/
├─ main.jsx, index.css          # точка входа; базовые стили, утилиты .no-scrollbar и .no-spinner
├─ App.jsx                      # маршрут { screen, params } через useState, без роутера
├─ context/FinanceContext.jsx   # общее состояние: история операций, накопления, цели, категории, настройки
├─ context/AppActionsContext.jsx# navigate, notify, общие диалоги операции и «О проекте»
├─ data/mockData.js             # ВСЕ тексты и витрина лендинга
├─ data/demoData.js             # генератор демо-истории за 12 месяцев до сегодняшнего дня (детерминированный)
├─ theme/colors.js              # единый источник цветов (импортируется в tailwind.config.js и в графики)
├─ theme/accents.js             # акцент → { hex, tile, dot } (классы Tailwind + HEX для Recharts)
├─ utils/format.js              # formatMoney (с валютой отображения), plural, fillTemplate и др.
├─ utils/dates.js               # даты: начало недели/месяца, подписи «Сегодня, 14:05», диапазоны
├─ utils/finance.js             # все расчёты из истории: периоды, столбцы, категории, сводка, подсказки, накопления, уведомления
├─ screens/                     # LandingPage, Dashboard, Savings, Analytics, Goals, Settings, TransactionsScreen
└─ components/
   ├─ ui/         # Button, Card, IconTile, TrendBadge, ProgressBar, SegmentedControl, Modal, Toast, Toggle, Reveal, LinkArrow, Logo, LeafMark
   ├─ charts/     # ExpenseDonut, DonutLegend, BalanceAreaChart, SpendingBarChart, IncomeExpenseChart, ChartTooltip
   ├─ cards/      # StatCard, ExpenseStructureCard (общие для лендинга и «Главной»)
   ├─ app/        # AppShell, Sidebar, Topbar, BottomNav, TransactionDialog, TransferDialog, Notifications/Onboarding/AboutDialog
   ├─ landing/    # секции лендинга + LaptopMockup (превью приложения на ноутбуке)
   ├─ dashboard/ savings/ analytics/ goals/ settings/   # карточки конкретных экранов
```

**Навигация.** `App.jsx` хранит `route = { screen, params }`. Экраны: `onboarding` (лендинг), `dashboard`, `savings`, `analytics`, `goals`, `settings`, `transactions` (вся история; открывается из «Все», поиска в шапке и категорий «Аналитики», params — `{ query }`, `{ categoryId }`, `{ type }`). Лендинг рисуется отдельно, остальные экраны внутри `AppShell`. Пункты меню берутся из `APP_NAV` (боковое меню) и `BOTTOM_NAV` (нижняя панель на телефоне: Главная, Аналитика, «+», Цели, Накопления) в `mockData.js`. Попасть в «Настройки» на телефоне можно кнопкой профиля в шапке. Вернуться на лендинг можно через логотип, «На сайт» или «Выйти из аккаунта».

**Состояние:**
- `FinanceContext` хранит историю операций основного счёта (с датами ISO), операции накопительного счёта, цели, категории и настройки (валюта, начало недели, язык, бюджет, «Скрывать баланс»). Всё сохраняется в `localStorage` (ключ `fin-money:demo:v2`). Баланс, показатели месяца, графики, подсказки и уведомления **считаются** функциями из `utils/finance.js`.
- При первом запуске (и по «Новые демо-данные») история строится генератором `createDemoData()` от текущей даты: баланс всегда 142 560 ₽ на момент генерации. «Начать с нуля» — пустые данные.
- Переводы (накопления, цели) нельзя изменить, только удалить — тогда откатывается и вторая сторона.
- **Тема.** `src/theme/colors.js` — две палитры (`palettes.light` / `palettes.dark`); Tailwind и графики берут цвета из CSS-переменных `--c-*` (`bg-card`, `text-ink`, `themeColor('brand')`). Класс `.dark` на `<html>` ставит `FinanceProvider` по настройке «Тема» (светлая / тёмная / авто), а до загрузки React — скрипт в `index.html`. Для карточек — `bg-card`, а не `bg-white`; для лёгких оттенков — `ink/5`, а не `black/5`.
- **CSV.** `utils/csv.js` — чтение и запись CSV (разделитель «;», BOM для Excel), кодировка файла UTF-8 или Windows-1251 (`decodeCsv`). `utils/statement.js` — операции ↔ строки выписки:
  - столбцы ищутся по заголовкам (`CSV_TEXTS.columns`, порядок вариантов — приоритет: «Сумма платежа» в валюте счёта важнее «Суммы операции»); «Тип» и «Статус» — только по точному названию;
  - сумма — один столбец со знаком или «Приход» / «Расход»; неудачные операции («Статус» FAILED, «отклонена») пропускаются;
  - переводы между своими счетами (`ownTransferWords`) — `type: 'transfer', kind: 'import'`: меняют баланс, но не доходы и расходы; перевод другому человеку — обычный расход;
  - возврат покупки (`refundWords`) — расход с плюсом (`amount > 0`): уменьшает траты своей категории; при правке остаётся возвратом;
  - повторы — по ключу «дата до минуты + сумма + описание» с учётом количества: одинаковые строки в файле сохраняются, повтором считается только то, что уже есть в Fin Money. Ключ хранится в операции (`importKey`), поэтому правка категории не ломает распознавание;
  - нераспознанные поступления — в «Прочие доходы» (`IMPORT_FALLBACK_INCOME`, категория добавляется при первом импорте).
- **Импорт пакетом.** `addTransactions(drafts, { fileName })` помечает операции `importId` и пишет запись в `state.imports`; `undoImport(id)` удаляет все операции пакета. История и «Отменить» — карточка `ImportsCard` в «Настройках».
- Лендинг — витрина: его цифры статичны (`SUMMARY`, `EXPENSE_CATEGORIES`, `SAVINGS_HISTORY`), кроме списка целей.

## 5. Реализованные этапы (все приняты пользователем)

1. **Лендинг (`onboarding`)** по десктопному макету: шапка с меню-якорями, первый экран с ноутбуком (`LaptopMockup` масштабируется через container-query единицы `cqw`/`em`), «Обзор», «Накопительный счёт» с графиком, «Категории», «Цели», тёмный баннер, подвал. Все кнопки «Мои финансы» ведут на «Главную».
2. **Главная:** баланс со скрытием суммы (глаз), «Пополнить» ведёт в «Накопления», «Перевести» ничего не делает; финансовая цель; доходы, расходы, превью накопительного счёта; структура расходов; последние 6 операций.
3. **Накопления:** карточка счёта, рабочий диалог «Пополнить / Снять» (снять больше баланса нельзя), «Доход по процентам», график баланса (Неделя / Месяц / Год), калькулятор доходности (ежемесячная капитализация, 12% годовых), история с фильтром, список целей.
4. **Аналитика:** периоды День / Неделя / Месяц / Год, три показателя, столбчатая диаграмма (последний столбец тёмный), категории с долями, «Доходы и расходы» за 6 месяцев, «Подсказки».
5. **Цели:** показатели, фильтр «Все / В процессе / Достигнуты», карточки с пополнением (переиспользует `AmountDialog`), создание цели (название, сумма, срок, иконка), кольцевая диаграмма распределения.
6. **Настройки:** профиль с формой и уведомлением «Изменения сохранены», месячный бюджет (ползунок, с 90% шкала красная), уведомления, параметры (валюта, начало недели, язык), безопасность, выход.
7. **Кнопки «+» и «Добавить операцию»:** диалог дохода или расхода с категорией, суммой и комментарием. Результат сразу виден на «Главной».
8. **Аналитика учитывает добавленные траты** (последний этап): итог, динамика (пересчитывается от суммы прошлого периода), среднее за день, «сегодняшний» столбец, категории и май в «Доходах и расходах». Применяется ко **всем** периодам, потому что операция датирована сегодняшним днём.

## 6. Принятые решения и причины

- **Веб вместо мобильного** — прямой запрос пользователя.
- **Единая схема цветов категорий** (в макетах она противоречила сама себе): Еда — green, Транспорт — blue, Развлечения — purple, Жильё — orange, Другое — gray. Задаётся в `EXPENSE_CATEGORIES`.
- **Реалистичные шкалы графиков.** В «Аналитике» ось Y подстраивается под данные: в мобильном макете было до 120k, но это не сходится с 63 200 ₽ за месяц. У графика накоплений ось Y начинается не с нуля, чтобы был виден рост.
- **Согласованные моковые данные.** Столбцы «Месяц» в сумме дают 63 200 ₽, за «Год» — 789 100 ₽. Суммы категорий равны итогу расходов, их доли в сумме дают 100%.
- **Сегодня в прототипе — 31 мая 2026.** Добавленные операции попадают в последний столбец периода, а для «Дня» — в столбец текущего часа (по реальному времени).
- **Без inline-стилей.** Динамические ширины задаются через `animate` во framer-motion, цвета графиков — через `theme/colors.js`. Grep по `style=` в `src` ничего не находит.
- **На телефоне у сеток экранов есть явный `grid-cols-1`.** Без этого карточки раздувались по самому широкому элементу и страница становилась шире экрана.
- **Вымышленные персональные данные** в «Настройках» (Маша, masha@example.com, +7 900 000-00-00).

## 9. Известные ограничения и недоработки (проверено по коду 30.10.2026)

Старые пункты этого раздела (нет сохранения, несвязанные экраны, кнопки-заглушки, статичные подсказки) закрыты этапами 1–3.

- **Только CSV.** Сбер для частных клиентов отдаёт выписку в PDF — её импорт запланирован отдельным этапом (нужна библиотека чтения PDF, ставить только с согласия пользователя).
- **Суммы в целых рублях.** Импорт округляет копейки, поэтому баланс может расходиться с банковским на несколько рублей. Переход на копейки — отдельный этап (смена формата данных с миграцией).
- **Категории из выписки** сопоставляются только по точному названию (или по описанию, совпадающему с названием категории). Остальное — в «Другое» / «Прочие доходы»; поправить можно в предпросмотре импорта. Словарь банковских категорий и правила «запомнить для похожих» — следующий этап.
- **Нет миграций формата данных.** Новые поля добавляются со значениями по умолчанию (`imports: []` в `restoreState`); несовместимая смена формата потребует миграции, а не новой версии ключа.
- **Переполнение `localStorage`** не показывается пользователю: сохранение молча не происходит.
- **Экспорт CSV** не экранирует ячейки, начинающиеся с `=`, `+`, `@` (Excel может принять их за формулу).
- **Playwright 1.48** — 2 уязвимости high в `npm audit` (только инструмент разработки, на сайт не влияют); обновление — с согласия пользователя.

**Результаты последних проверок (этап А):** `npm run lint` чистый, `npm test` — 41 тест, `npm run test:e2e` — 8 тестов (в том числе импорт выписки в Windows-1251 с правкой строк и отменой). Окно импорта проверено в браузере на 1280 и 375 px, в светлой и тёмной теме, горизонтальной прокрутки нет.

## 11. Следующий шаг

План после исследования 30.10.2026 (этапы согласовываются по одному):

- **Б** — импорт PDF-выписки Сбера (нужен обезличенный образец от пользователя и согласие на библиотеку).
- **В** — автокатегории: словарь банковских категорий, правила «запомнить для похожих», разбор «Другого».
- **Г** — суммы в копейках, миграции формата, несколько счетов.
- **Д** — бюджеты по категориям, сверка с остатком банка.
- **Е** — сервер и аккаунты. Если хранить реальные выписки, это персональные данные: нужен российский хостинг PostgreSQL (152-ФЗ), а не Supabase. Для демо-режима «Войти как гость» это не требуется.

Подключение к банкам по API пока не планируется: Сбер ID даёт только вход и профиль, а не операции; открытые API Банка России доступны зарегистрированным участникам рынка.

**Первое действие в новом чате:** прочитать `контекст.txt` и этот файл, запустить `npm run lint`, `npm test` и `npm run build`, спросить пользователя, какой этап делать.
