## 1. Цель проекта

Интерактивный frontend-прототип финансового приложения **Fin Money** (UI-кит и демо для показа инвесторам). Бэкенда нет, все данные моковые.

**Важно:** изначально по `контекст.txt` и мобильному макету это был мобильный интерфейс в рамке телефона. Позже пользователь **явно попросил перейти на веб-версию** по десктопному макету лендинга, а затем сделать в веб-стиле и все экраны. Сейчас проект — адаптивное **веб-приложение**: на десктопе боковое меню, на телефоне нижняя панель, как в мобильном макете. Рамки телефона больше нет.

## 2. Технологии (установленные версии из `node_modules`)

| Пакет | Версия | Назначение |
|---|---|---|
| react / react-dom | 18.3.1 | UI, только функциональные компоненты и хуки |
| vite + @vitejs/plugin-react | 5.4.21 | сборка и dev-сервер |
| tailwindcss (+ postcss, autoprefixer) | 3.4.19 | все стили через `className` |
| recharts | 2.15.4 | все графики (обязательное требование) |
| framer-motion | 11.18.2 | анимации |
| lucide-react | 0.460.0 | все иконки (обязательное требование) |

Шрифт Manrope подключается из Google Fonts в `index.html`. Сторонних UI-библиотек нет и быть не должно.

## 3. Команды

```bash
npm install        # установка зависимостей
npm run dev        # dev-сервер (Vite), по умолчанию http://localhost:5173
```

**Проверка:** автотестов и линтера в проекте нет. Проверяли так: `npm run build` плюс ручной просмотр в браузере на ширине 1440px и 375px.

## 4. Архитектура

```
src/
├─ main.jsx, index.css          # точка входа; базовые стили, утилиты .no-scrollbar и .no-spinner
├─ App.jsx                      # переключение «лендинг ↔ приложение» через useState, без роутера
├─ context/FinanceContext.jsx   # общее состояние: добавленные операции → summary, categories, transactions
├─ data/mockData.js             # ВСЕ тексты и числа (~610 строк)
├─ theme/colors.js              # единый источник цветов (импортируется в tailwind.config.js и в графики)
├─ theme/accents.js             # акцент → { hex, tile, dot } (классы Tailwind + HEX для Recharts)
├─ utils/format.js              # formatMoney, formatSignedMoney, formatCompact, formatTrend, toPercent, monthlyPayment, scaleCategories
├─ utils/analytics.js           # учёт добавленных трат: категории, «сегодняшний» столбец, пересчёт динамики
├─ screens/                     # LandingPage, DashboardScreen, SavingsScreen, AnalyticsScreen, GoalsScreen, SettingsScreen
└─ components/
   ├─ ui/         # Button, Card, IconTile, TrendBadge, ProgressBar, SegmentedControl, Modal, Toast, Toggle, Reveal, LinkArrow, Logo, LeafMark
   ├─ charts/     # ExpenseDonut, DonutLegend, BalanceAreaChart, SpendingBarChart, IncomeExpenseChart, ChartTooltip
   ├─ cards/      # StatCard, ExpenseStructureCard (общие для лендинга и «Главной»)
   ├─ app/        # AppShell, Sidebar, Topbar, BottomNav, AddTransactionDialog
   ├─ landing/    # секции лендинга + LaptopMockup (превью приложения на ноутбуке)
   ├─ dashboard/ savings/ analytics/ goals/ settings/   # карточки конкретных экранов
```

**Навигация.** `App.jsx` хранит `activeScreen`. Возможные значения: `onboarding` (лендинг), `dashboard`, `savings`, `analytics`, `goals`, `settings`. Лендинг рисуется отдельно, остальные экраны внутри `AppShell`. Пункты меню берутся из `APP_NAV` (боковое меню) и `BOTTOM_NAV` (нижняя панель на телефоне: Главная, Аналитика, «+», Цели, Накопления) в `mockData.js`. Попасть в «Настройки» на телефоне можно кнопкой профиля в шапке. Вернуться на лендинг можно через логотип, «На сайт» или «Выйти из аккаунта».

**Состояние:**
- `FinanceContext` (оборачивает всё приложение в `App.jsx`) хранит только операции, добавленные через диалог «Добавить операцию». Из них считаются баланс, доходы, расходы, категории и список операций. Это видно на «Главной» и в «Аналитике».
- Остальное состояние **локальное в экранах**: баланс и история «Накоплений», список целей, поля «Настроек». Оно сбрасывается при уходе с экрана или перезагрузке.

## 5. Реализованные этапы (все приняты пользователем)

1. **Лендинг (`onboarding`)** по десктопному макету: шапка с меню-якорями, первый экран с ноутбуком (`LaptopMockup` масштабируется через container-query единицы `cqw`/`em`), «Обзор», «Накопительный счёт» с графиком, «Категории», «Цели», тёмный баннер, подвал. Все кнопки «Начать» ведут на «Главную».
2. **Главная:** баланс со скрытием суммы (глаз), «Пополнить» ведёт в «Накопления», «Перевести» ничего не делает; финансовая цель; доходы, расходы, превью накопительного счёта; структура расходов; последние 6 операций.
3. **Накопления:** карточка счёта, рабочий диалог «Пополнить / Снять» (снять больше баланса нельзя), «Доход по процентам», график баланса (Неделя / Месяц / Год), калькулятор доходности (ежемесячная капитализация, 12% годовых), история с фильтром, список целей.
4. **Аналитика:** периоды День / Неделя / Месяц / Год, три показателя, столбчатая диаграмма (последний столбец тёмный), категории с долями, «Доходы и расходы» за 6 месяцев, «Подсказки».
5. **Цели:** показатели, фильтр «Все / В процессе / Достигнуты», карточки с пополнением (переиспользует `AmountDialog`), создание цели (название, сумма, срок, иконка), кольцевая диаграмма распределения.
6. **Настройки:** профиль с формой и уведомлением «Изменения сохранены», месячный бюджет (ползунок, с 90% шкала красная), уведомления, параметры (валюта, начало недели, язык), безопасность, выход.
7. **Кнопки «+» и «Добавить операцию»:** диалог дохода или расхода с категорией, суммой и комментарием. Результат сразу виден на «Главной».
8. **Аналитика учитывает добавленные траты** (последний этап): итог, динамика (пересчитывается от суммы прошлого периода), среднее за день, «сегодняшний» столбец, категории и май в «Доходах и расходах». Применяется ко **всем** периодам, потому что операция датирована сегодняшним днём.

## 6. Принятые решения и причины

- **Веб вместо мобильного** — прямой запрос пользователя.
- **Единая схема цветов категорий** (в макетах она противоречила сама себе): Еда — green, Транспорт — blue, Развлечения — purple, Жильё — orange, Другое — gray. Задаётся в `EXPENSE_CATEGORIES`.
- **Реалистичные шкалы графиков.** В «Аналитике» ось Y подстраивается под данные: в мобильном макете было до 120k, но это не сходится с 63 200 ₽ за месяц. У графика накоплений ось Y начинается не с нуля, чтобы был виден рост.
- **Согласованные моковые данные.** Столбцы «Месяц» в сумме дают 63 200 ₽, за «Год» — 789 100 ₽. Суммы категорий равны итогу расходов, их доли в сумме дают 100%.
- **Сегодня в прототипе — 31 мая 2026.** Добавленные операции попадают в последний столбец периода, а для «Дня» — в столбец текущего часа (по реальному времени).
- **Без inline-стилей.** Динамические ширины задаются через `animate` во framer-motion, цвета графиков — через `theme/colors.js`. Grep по `style=` в `src` ничего не находит.
- **На телефоне у сеток экранов есть явный `grid-cols-1`.** Без этого карточки раздувались по самому широкому элементу и страница становилась шире экрана.
- **Вымышленные персональные данные** в «Настройках» (Алексей Смирнов, alexey@example.com, +7 900 000-00-00).

## 9. Известные ограничения и недоработки (проверено по коду)

- **Нет git-репозитория** (`git status`: `fatal: not a git repository`). Коммитов нет, изменения нигде не зафиксированы. Пользователю стоит предложить `git init` (`.gitignore` с `node_modules` и `dist` уже есть).
- **Большой бандл.** `npm run build` предупреждает: JS-чанк 786 КБ (gzip 227 КБ), лимит 500 КБ. Code-splitting не делали.
- **Данные сбрасываются при перезагрузке страницы.** Хранилища (`localStorage` или бэкенда) нет.
- **Состояние экранов не связано между собой:**
  - пополнения «Накоплений» не меняют общий баланс на «Главной» и сбрасываются при уходе с экрана;
  - новые и пополненные цели не видны на «Главной», лендинге и в «Накоплениях» (там статичный `GOALS`);
  - «Скрывать баланс» в «Настройках» не связан с глазом на «Главной»;
  - бюджет в «Настройках» берёт исходные расходы `SUMMARY`, а не значение из `FinanceContext`.
- **Статичные тексты:** «Подсказки» в «Аналитике» (например, «Еда — 32%») не пересчитываются. Бейджи динамики на «Главной» (+18%, +6%) тоже статичны, пересчитывается только «Аналитика».
- **Кнопки без действия:** колокольчик, поиск, «Перевести», кнопка календаря в «Аналитике», клики по категориям, ссылки «Все ›», «Сменить пароль», «Активные устройства», ссылки подвала (`href="#"`).
- **Нет ограничения на сумму новой цели** (при проверке форма приняла 6 млрд ₽). Пользователю предлагали лимит, ответа не было.
- **Мелочи:** в `tailwind.config.js` остались неиспользуемые токены `height.phone`, `borderRadius.phone`, `boxShadow.phone` от времён рамки телефона. На странице «Настроек» два компонента `Toast` (свой и из `AppShell`).

**Результаты последних проверок:** `npm run build` проходит без ошибок, есть только предупреждение о размере чанка. В браузере проверены все экраны на ширине 1440px и 375px, горизонтальной прокрутки нет. Проверено вживую: добавление операции обновляет «Главную» и «Аналитику», работают пополнение и снятие, создание цели, сохранение профиля с уведомлением и предупреждение бюджета.
